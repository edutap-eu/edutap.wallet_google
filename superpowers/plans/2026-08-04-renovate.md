# Renovate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the GitHub-Actions-only Dependabot configuration with a Renovate configuration that also watches the Python dependencies, matching the setup already running in `edutap.data_provider`.

**Architecture:** Two files change and one is deleted. Renovate itself runs as the hosted Mend GitHub App on the `edutap-eu` organisation; this branch only supplies its configuration. There is no workflow to write and no secret to store.

**Tech Stack:** Renovate (hosted Mend app), JSON5, GitHub Actions, pre-commit.ci.

**Spec:** `superpowers/specs/2026-08-04-renovate-design.md` — read it before starting. It explains *why* the hosted app rather than a self-hosted workflow, and why two of data_provider's rules are deliberately not copied.

## Global Constraints

- Branch: `chore/renovate`, already created from `main`. Never commit to `main`. Never `git push` — the user pushes.
- Conventional Commits. Commit messages, comments and identifiers in English.
- This branch goes to `main` **before** `chore/httpx2-migration`. The two are independent.
- The file is `renovate.json5`, not `renovate.json`. JSON5 is chosen so the reasoning for each rule lives beside the rule; a comment explaining *why* is as much a deliverable here as the rule itself.
- No `automerge` anywhere, at any level.
- Do **not** add `:enablePreCommit`. pre-commit.ci already opens those pull requests — `.pre-commit-config.yaml` carries a `ci:` block with `autoupdate_schedule: monthly`.
- Do **not** add `lockFileMaintenance`. PR #93 removed `uv.lock`; there is no lockfile in the repository.
- Renovate itself cannot be tested from this branch. The verification is schema validation plus a careful read.

### Task 1: The Renovate configuration

**Files:**
- Create: `renovate.json5`

**Interfaces:**
- Consumes: nothing.
- Produces: `renovate.json5` at the repository root, the path the Mend app discovers automatically. Task 2 refers to its `github-actions` manager rule as the reason Dependabot goes.

- [ ] **Step 1: Write the configuration**

Create `renovate.json5` with exactly this content. The comments are not decoration — they are the reason the file is JSON5 rather than JSON.

```json5
// Renovate configuration. JSON5 rather than JSON so the reasoning can live next to
// the rules — this file decides what arrives unasked in the pull request list, and
// a rule nobody understands is a rule somebody switches off.
//
// Renovate runs as the hosted Mend app, installed on the edutap-eu organisation;
// there is no workflow of ours that drives it. A self-hosted run authenticating
// with GITHUB_TOKEN would open pull requests that GitHub refuses to let trigger
// workflows, so every update would arrive untested. An app token does not have
// that defect, but it needs a GitHub App installed on the organisation *plus* a
// workflow file and two repository secrets — the same prerequisite as the hosted
// app, for more machinery.
{
  $schema: "https://docs.renovatebot.com/renovate-schema.json",

  extends: [
    "config:recommended",
    // Once a week, before 4 AM. Dependency updates are not news; a Monday morning
    // batch is read, a stream through the week is dismissed.
    "schedule:earlyMondays",
  ],

  timezone: "Europe/Berlin",

  // Deliberately absent, so a later reader does not mistake either for an oversight:
  //
  // `:enablePreCommit` — .pre-commit-config.yaml carries a `ci:` block with
  // `autoupdate_schedule: monthly`, so pre-commit.ci already opens the pull requests
  // that bump those revisions. Enabling Renovate's pre-commit manager as well would
  // produce two pull requests per hook, the same trap as running Dependabot and
  // Renovate on GitHub Actions at once. This is also why `ruff` needs no rule of its
  // own here, unlike in edutap.data_provider: it is pinned by revision in
  // .pre-commit-config.yaml, not as a version range in pyproject.toml.
  //
  // `lockFileMaintenance` — there is no lockfile. uv.lock stopped being tracked in
  // PR #93, on the grounds that a library's consumers resolve the ranges in
  // pyproject.toml and never read it.

  // No automerge anywhere. Green CI proves the suite still passes, not that the
  // update is one we want.
  packageRules: [
    {
      matchManagers: ["github-actions"],
      groupName: "GitHub Actions",
    },
    {
      // Everything under [project.optional-dependencies] — the callback, test,
      // typecheck and develop extras. None of it is installed by a consumer of the
      // library, so one pull request for the batch is proportionate.
      matchManagers: ["pep621"],
      matchDepTypes: ["project.optional-dependencies"],
      groupName: "development dependencies",
    },
    {
      // The runtime dependencies, which every consumer of this library resolves
      // against. Each one on its own, so the pull request is about that library.
      //
      // These carry lower bounds rather than bare names since PR #93, and several
      // of those bounds exist to pin out a specific advisory — read the comment
      // beside the dependency in pyproject.toml before lowering one.
      matchManagers: ["pep621"],
      matchDepTypes: ["project.dependencies"],
      groupName: null,
    },
  ],
}
```

- [ ] **Step 2: Verify it is valid JSON5 and matches the Renovate schema**

Run:

```bash
npx --yes --package renovate -- renovate-config-validator
```

Needs Node ≥22. This environment's default `node` on `PATH` can be as old as
v10.24.1, under which the command fails with `npx: command not found:
renovate` — a message that reads like a missing package, not an unsupported
Node. Switch to a current Node first (`nvm use --lts` worked here).

Deliberately no file argument: passing `renovate.json5` explicitly validates
it as *global* config, whereas leaving the argument off auto-discovers it and
validates it as the *repository* config it actually is.

Expected: `INFO: Config validated successfully`.

If `npx` is unavailable, at minimum verify the file parses:

```bash
python3 -c "import json5, pathlib; json5.loads(pathlib.Path('renovate.json5').read_text()); print('parses')"
```

(`uvx --with json5 python3 -c ...` if `json5` is not installed.) A parse check is weaker than the validator — it catches a stray comma but not a misspelled option name, and Renovate silently ignores options it does not recognise. Prefer the validator.

- [ ] **Step 3: Re-read the file against the spec**

There is no test that can run Renovate from here. Instead, check these five by eye:

1. No `automerge` key anywhere, at any nesting level.
2. No `:enablePreCommit` in `extends`.
3. No `lockFileMaintenance` key.
4. `groupName: null` on the runtime-dependency rule — `null`, not omitted. Omitting it would let `config:recommended`'s own grouping apply.
5. The two "deliberately absent" comments are present. They are the deliverable that stops someone re-adding those options in six months.

- [ ] **Step 4: Commit**

```bash
git add renovate.json5
git commit -m "chore: configure Renovate for dependency updates

Follows edutap.data_provider's renovate.json5: hosted Mend app rather than a
self-hosted workflow, weekly Monday batch, no automerge, GitHub Actions and
the optional-dependency extras grouped, runtime dependencies one per pull
request.

Records why two of that file's rules are not copied here: pre-commit.ci
already opens the hook-revision pull requests, and PR #93 left no uv.lock to
maintain."
```

### Task 2: Retire Dependabot and document what replaced it

**Files:**
- Delete: `.github/dependabot.yml`
- Modify: `CONTRIBUTING.md`

**Interfaces:**
- Consumes: the `github-actions` manager rule from Task 1 — deleting Dependabot is only safe because Renovate now covers that ecosystem.
- Produces: nothing consumed later.

- [ ] **Step 1: Confirm what Dependabot actually covers**

Run: `cat .github/dependabot.yml`

Expected: a single `updates:` entry, `package-ecosystem: "github-actions"`, weekly. Nothing else. If it covers more than that by the time you read this, stop and re-check the spec — the argument for deleting it is that Renovate covers everything it does.

- [ ] **Step 2: Delete it**

```bash
git rm .github/dependabot.yml
```

Deleting this file does **not** disable Dependabot **security alerts**. Those are a repository setting, not something `dependabot.yml` controls, and they stay on. Do not "helpfully" turn them off.

- [ ] **Step 3: Record the change for contributors**

Read `CONTRIBUTING.md` first and match its heading level and tone. Add a short section — if there is an existing section about CI or maintenance, put it there rather than at the end:

```markdown
## Dependency updates

Dependency updates arrive as pull requests from two bots, neither of which
merges anything on its own:

- **Renovate** (hosted Mend app, configured in `renovate.json5`) watches the
  dependencies in `pyproject.toml` and the actions in `.github/workflows/`.
  It opens pull requests once a week, on Monday morning.
- **pre-commit.ci** watches the hook revisions in `.pre-commit-config.yaml`
  and opens a pull request monthly.

Renovate also maintains a "Dependency Dashboard" issue listing everything it
is holding back. If Renovate appears to have stopped, check that issue first.
```

- [ ] **Step 4: Verify nothing else references Dependabot**

Run: `grep -rn -i "dependabot" --exclude-dir=.git .`

Expected: only the new `CONTRIBUTING.md` section if you mentioned it there, and any historical mention in a changelog. A live reference in a workflow or in the documentation must be updated.

- [ ] **Step 5: Commit**

```bash
git add -A .github/dependabot.yml CONTRIBUTING.md
git commit -m "chore: retire Dependabot in favour of Renovate

dependabot.yml covered GitHub Actions and nothing else, which renovate.json5
now covers too; leaving both configured produces two pull requests for every
action bump.

This does not affect Dependabot security alerts, which are a repository
setting rather than something this file controls."
```

### Task 3: Verification and pull request preparation

**Files:** none modified.

**Interfaces:**
- Consumes: Tasks 1-2.
- Produces: a branch ready for review.

- [ ] **Step 1: Run the linters**

Run: `uvx --with tox-uv tox -e lint`

Expected: PASS. The pre-commit suite includes `end-of-file-fixer`, `trailing-whitespace` and `codespell`, all of which read the two files touched here. `check-json` does **not** cover `renovate.json5` — JSON5 is not JSON, and the hook would reject the comments if it did match. Confirm the hook's file pattern does not pick it up; if it does, exclude `renovate.json5` there rather than removing the comments.

- [ ] **Step 2: Review the diff**

Run: `git diff origin/main...HEAD` — `origin/main`, not local `main`, since a worktree's local `main` ref is easily stale and a diff against it can pull in unrelated commits.

Expected: `renovate.json5` added, `.github/dependabot.yml` deleted, `CONTRIBUTING.md` and `superpowers/` additions. Nothing under `src/` or `tests/` — this branch changes no code.

- [ ] **Step 3: Write the pull request description**

It must state, prominently:

1. **The Mend Renovate app is already installed on the `edutap-eu` organisation**, org-wide — there is no install-or-grant step left. What's still open is confirming this repository gets onboarded on the Mend side once this merges.
2. The failure mode of onboarding not happening is **silence**, not an error — so after merging, check that Renovate opens its "Dependency Dashboard" issue in this repository.
3. The first run is expected to be quiet, not noisy: GitHub Actions here are already current, and the runtime-dependency rule's open `>=` floors mean the pep621 manager yields close to nothing (see `renovate.json5`'s comments). Realistically zero to one pull request, not one per dependency.
4. Dependabot security alerts are unaffected, and are in fact the mechanism that keeps the runtime-dependency floors current going forward — see `renovate.json5`.

- [ ] **Step 4: Stop**

Do not push. The user pushes and opens the pull request.
